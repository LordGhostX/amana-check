# Amana Check — constraints matrix

The OSF × Andela brief defines seven operating constraints. This matrix maps each one to what is actually built, where it lives, and how the demo shows it.

| Constraint                       | How Amana Check answers it                                                                                                                                                                                                                              | Where                                                                                             | Demo evidence                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Trust and verification           | Sources are tiered (T1 official, T2 independent, T3 media); answers carry citations, publisher, publication date, and “checked” time; corrections are versioned; “unknown” is a valid status.                                                           | `src/lib/trust/freshness.ts`, `src/lib/pipeline/synthesize.ts`, `src/lib/db/schema.ts`            | Answer card shows status, cited bullets, and source excerpts; eval enforces 100% citation validity.              |
| Low bandwidth and limited access | Server-rendered, text-first interface with no images or video, small payloads, no client framework beyond React islands, and an English UI that browsers can translate.                                                                                 | `src/app/page.tsx`, `src/app/check-form.tsx`, `src/app/answer-card.tsx`                           | Load the site on a throttled connection; the check flow still works.                                             |
| Accessibility and inclusion      | Plain-language answer structure (what we know, what we don’t know, what to do now), large controls, semantic headings, status labels with text (not colour alone), machine-translation labels, and honest phrasing for low-literacy contexts.           | `src/app/answer-card.tsx`, `src/app/methodology/page.tsx`                                         | Screen-reader pass and simple-language bullets in answer cards.                                                  |
| Privacy and security             | No accounts, no raw IPs, HMAC-only rate limits and locale hints, isolated tables with no join keys to checks, ZDR and no-training model routing with fail-closed behaviour, admin sessions signed and expiring, script injection blocked and tested.    | `src/lib/locale/hash.ts`, `src/lib/llm/client.ts`, `src/lib/admin/auth.ts`, `scripts/red-team.ts` | `bun run red-team` verifies HMAC usage, identifier-free checks, and token rejection.                             |
| Multilingual access              | Any-language input is detected and answered in the same language, with English fallback; the reply-in-kind path covers English, Nigerian Pidgin, Yoruba, Igbo, Hausa, and Swahili today.                                                                | `src/lib/llm/prompts.ts`, `src/lib/pipeline/extract.ts`, `src/lib/pipeline/synthesize.ts`         | Eval set includes Pidgin, Hausa, Yoruba, Igbo, and Swahili claims; latest language accuracy is 7/7.              |
| Local relevance                  | Nationwide region registries for Nigeria (36 states + FCT) and Kenya (47 counties), location precedence from claim to national, per-country referral pathways, and source packs that can be extended to other countries.                                | `data/regions/`, `data/sources/`, `data/referrals/`, `src/lib/locale/precedence.ts`               | Ask a claim mentioning a specific state or county and watch the corpus narrow to it.                             |
| Clear next steps                 | Every answer ends with practical actions; referral contacts are injected into synthesis with verified/unverified labels; the model is forbidden from inventing contacts, fees, or links; a public Get help page lists pathways with verification dates. | `src/lib/referrals/lookup.ts`, `src/lib/pipeline/synthesize.ts`, `src/app/help/page.tsx`          | NCDC 6232 appears as verified, while unverified numbers are marked “confirm locally”, including in Hausa output. |

## How the demo covers all seven in one interaction

A single forwarded message pasted on the home page produces an answer card containing: the detected language, a status with reason (trust), a source list with dates (freshness and verification), plain-language bullets (accessibility), a response in the user's language (multilingual), location-aware evidence (local relevance), and contact next steps (action). The privacy and low-bandwidth constraints are structural rather than visible, and are documented on the methodology page and in `docs/threat-model.md`.
